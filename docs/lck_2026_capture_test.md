# 2026 LCK 실제 과거 데이터 테스트

## 선택 경기

- 2026년 9월 13일 LCK 결승: Gen.G Esports vs Hanwha Life Esports, **1세트**.
- Match ID: `117030752644841643`, Game ID: `117030752644841644`.
- 공식 일정: https://lolesports.com/en-GB/schedule?leagues=lck
- 공개 일정 HTML의 Apollo SSR 데이터에서 날짜·리그·팀·세트 ID를 확인했다. 웹페이지 코드를 실행하거나 인증 키를 추출하지 않았다.
- 각 window/details 요청은 **인증 키·유료 구독 없이 HTTP 200**이었다.

## 원본과 범위

원본 저장 위치: `fixtures/captures/lck-2026-09-13-gen-hle-game1/`.

- 연속 구간: UTC `2026-09-13T05:45:00.550Z` ~ `05:46:09.813Z` (약69.263초).
- 원본 프레임 363개, 고유 timestamp 333개, 동일 중복 30개.
- 10초 window 7개, 같은 킬 구간의 details, 별도 종료 window를 보관한다.
- `manifest.json`에 요청 URL·HTTP 상태·원본 SHA-256·캡처 시각을 보관한다.
- `frames.json`은 현재 서버 모델용 정규화 데이터다. 원본 파일은 변경하지 않는다.
- 종료 스냅샷은 연속 재생 구간과 별개다. **전체 경기 기록은 아니다.**

- 원본 timestamp는 관측 시각이며 실제 처치 발생 시각으로 단정하지 않는다. 처치 상대도 추정하지 않는다.

## 검증 및 수정

실제 캡처용 테스트 7개와 기존 테스트 20개, **전체 서버 테스트 27개 통과**.

1. 원본 파일 해시, 2026년 경기·세트 ID 검증.
2. 팀 통계 정규화와 원본 일치, 누락 게임 시계 유지.
3. 실제 킬 2건과 20초 관측 집계 검증.
4. 선수별 킬 획득 및 window/details 교차검증.
5. 메모리 저장 중복 방지와 SSE 커서 재전송.
6. 종료 상태 검증, 확인되지 않은 승자 생성 방지.
7. 캡처 데이터 Provider로 수집기 → REST /sync → 로그 → SSE 재동기화 통합 검증.

발견한 문제: Detector를 직접 호출할 때 동일 프레임 재전송을 정정으로 처리해 보류 킬 집계를 소거했다. 정확히 동일한 프레임은 조기 반환하도록 수정했다. 실제 캡처 테스트에서 실패를 확인한 후 수정했고 전체 테스트가 통과했다.

재현:

```sh
python -m pytest apps/server/tests
```

## 검증하지 않은 것

- 현재 경기의 자동 발견·지속적인 라이브 조회·방송 대비 지연.
- 전체 경기 재생과 데스크톱 UI에 이 캡처를 연결하는 기능.
- 실제 게임 내부 시계: 응답에 없으므로 gameTimeSeconds는 null이다.
- 1세트 공식 승자: 캡처한 메타데이터에 없으므로 생성하지 않는다. 전체 시리즈의 공식 3:1 결과와 혼동하지 않는다.
- 밴픽 진행 순서·밴 목록·킬 주체와 피해자의 사건별 연결.
