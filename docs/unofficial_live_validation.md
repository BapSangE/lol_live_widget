# 공개 비공식 라이브 공급원 검증 — 2026-10-16

목표: 개인용 위젯에서 API 키 없이 공개 경기 일정 및 통계를 수집한다.

## 실제 외부 응답으로 확인한 범위

- 공개 일정: `https://lolesports.com/en-US/schedule?leagues=worlds`. 308 → 307 → 200 리디렉션을 거쳐 `/en-US/leagues/worlds`의 HTML을 수신했다.
- HTML의 `ApolloSSRDataTransport` 스크립트 안 `EventMatch` JSON만 파싱한다. JavaScript를 실행하지 않으며 페이지의 다른 설정이나 키를 사용하지 않는다.
- 실제 서버의 `/api/v1/health`: `status=ok`, `sourceMode=live`, `sourceStatus=available`, 공급원 오류 0건.
- `/api/v1/matches?league=worlds`: 앞으로의 Worlds 일정 40건, 진행 중 경기 0건.
- 가장 가까운 일정: match `115660588583171790`, UTC `2026-10-16T18:00:00Z` / 한국 시간 10월17일 03:00, 공개 페이지 기준 TBD–KC.
- 공개 과거 경기 통계: `https://feed.lolesports.com/livestats/v1/window/115660588583171787?startingTime=2026-10-15T18%3A45%3A00Z`, 키 없는 요청 HTTP 200. 프레임 51개, UTC 18:45:00.225~18:45:09.512, KC 1킬 / C9 14킬.
- 통계 feed의 `startingTime` 미지정 요청은 과거 첫 구간을 반환했다. 라이브에서는 시각을 명시하고 여러 10초 구간을 이어받는다.

## 자동 검증

공개 공급자 테스트는 경기 JSON 파싱·팀 ID·중복·과거 경기 제외, 세트 전환, 종료 프레임까지 수집, 연속 window 조회, 결측 구간 복구, 429 이후 공유 일정 재시도 방지, 접근 거절, 명시적 opt-in, 페이지 형식 변경, 리디렉션을 검증한다. 기존 서버 테스트 및 위젯 테스트도 함께 실행한다.

최종 로컬 결과: 서버 40/40, 위젯 17/17 통과. TypeScript 검사와 Vite 프로덕션 빌드, 변경 Python 파일 Ruff 검사, `git diff --check` 통과. 기존 Starlette TestClient deprecation 경고 1건은 남아 있다.

검토 중 재현한 결함과 수정:

- 일정이 먼저 종료되면 과거 중첩 프레임도 종료로 취급해 최종 통계를 누락했다. feed의 `gameState=finished`로 종료를 판별하도록 수정했다.
- 일정 요청 429 후 경기별 상세 갱신이 같은 URL을 즉시 재요청했다. 실패한 일정 갱신은 중앙 수집기의 다음 재시도까지 캐시를 사용하도록 수정했다.
- 긴 빈 feed 구간에서 매번 같은 범위를 조회했다. 마지막 관측 프레임과 별도로 조회 진행 위치를 기억한다.
- 정상 연결 후 진행 중 경기가 없으면 위젯이 `연결 끊김`을 표시했다. `경기 대기`로 수정했다.

## 남은 실전 검증

- 실제 경기 진행 중 자동 발견과 여러 차례의 통계 증가.
- 수집 → 이벤트 감지 → REST/SSE → 화면 표시의 실시간 연결.
- 실제 세트 교체와 경기 종료의 최종 통계 및 이벤트.
- 공개 일정 캐시 지연, feed 지연과 방송 대비 실측 지연.

검토에서 남긴 작은 운영 과제: 일정 조회가 실패한 상태에서 통계 feed만 성공하면 기존 공용 health 처리로 공급원이 정상으로 표시될 수 있다. 일정과 통계 feed의 오류 상태를 개별 보존하는 개선은 이번 범위에서 보류했다.

이 기록의 과거 경기 feed 응답을 실제 라이브 수신으로 해석하지 않는다. 게임 내부 시계와 공식 승자 등 응답에 없는 필드는 생성하지 않는다.

실행: `.venv312/bin/python scripts/run_live.py`. 서버 `127.0.0.1:8000`, 위젯 `127.0.0.1:1420`. `SOURCE_APPROVED=true`는 사용자가 선택한 공개 수집 모드의 명시적 opt-in이며, API 인증 정보나 외부 서비스의 승인 증명은 아니다.
